# Library guide

This directory is the GitHub-safe export of the local Tesla collection. Each
source has one UTF-8 text file with explicit page markers. The catalog records
the title, creator, evidence tier, rights state, extraction status, original
filename, size, and SHA-256 checksum, but never the original local path.

## Categories

| Directory | Contents | Publishing rule |
|---|---|---|
| `public-domain/` | Historical works marked public domain | May be suitable for a public edition after checking jurisdiction and source terms |
| `research-only/` | Copyrighted, uncertain, or unverified material | Keep private unless permission or a rights review allows publication |
| `research-leads/` | Saved YouTube transcripts and archived web pages that mention Tesla | Use only to find claims worth checking; do not treat as evidence |
| `personal-notes/` | Personal notes and saved research leads | Keep private until quotations and third-party excerpts are reviewed |

## Evidence tiers

- **A:** primary evidence, such as Tesla's writing, patents, or contemporary records.
- **B:** strong scholarly context or an edited primary source.
- **C:** useful secondary interpretation.
- **D:** leads, personal notes, or unverified material that cannot support a claim alone.

## Known gaps

- `anderson-tesla-work-interview` is a scan with only a small amount of embedded
  text. Its catalog entry is marked `needs-ocr`.
- `tesla-complete-us-patents-local-499` is an alternate 499-page patent scan
  with almost no embedded text. It is retained for comparison with the
  searchable 429-page compilation and marked `needs-ocr`.
- `personal-notes-nikola-tesla` preserves an empty one-byte source file as an
  empty cataloged placeholder.
- An evidence tier describes research value; it does not describe copyright
  status or factual correctness.
- The 52 research leads were selected because their local text or filename
  contains a Tesla-specific term. Many are only tangentially related and are
  intentionally isolated from stronger material.

The exports are generated by `npm run research:export`. The local ingest files
under `research/derived/` remain ignored because their manifests contain
machine-specific paths and the pages/chunks duplicate this archive.
